# דשבורד חשיפות חיסכון

דשבורד סטטי (HTML + JS, ללא שרת) להצגת חשיפות מצרפיות של מוצרי חיסכון —
גמל, השתלמות, פנסיה ופוליסות חיסכון — על בסיס הנתונים הציבוריים של רשות שוק
ההון (גמל-נט, פנסיה-נט, ביטוח-נט) כפי שפורסמו ב-data.gov.il.

היתרות ודמי הניהול שהמשתמש מזין נשמרים בדפדפן בלבד (localStorage).
הדשבורד מציג נתונים להמחשה בלבד ואינו מהווה ייעוץ או המלצה.

## מבנה הפרויקט

| קובץ | תפקיד |
|---|---|
| `index.html` | הדף — מבנה ועיצוב |
| `scripts.js` | כל הלוגיקה (נטען בסוף הדף; מקור האמת היחיד לקוד) |
| `funds_unified.json` | מאגר הקופות המאוחד שהדשבורד קורא |
| `tools/build_dataset.py` | בניית המאגר מקובצי המקור + בדיקות שפיות |
| `tools/fix_csv_encoding.py` | תיקון קידוד של קובץ מקור שאקסל מציג כג'יבריש |
| `logos/` | לוגואים של החברות המנהלות (אופציונלי — ראה `logos/README.md`) |
| `netlify.toml` | הגדרות הפרסום ל-Netlify |

## פרסום (Netlify)

האתר מתפרסם ב-Netlify מענף `main`. פקודת הבנייה מעתיקה את קובצי האתר
לתיקיית `_site` (שאינה נשמרת ב-git) ומייצרת ממנה גם `404.html`:

```bash
mkdir -p _site
cp index.html styles.css scripts.js funds_unified.json _site/
cp index.html _site/404.html
mkdir -p _site/logos
cp logos/*.svg logos/*.png _site/logos/ 2>/dev/null || true
```

חיבור ראשוני: ב-Netlify בוחרים **Add new site → Import an existing project**,
מחברים את הריפו הזה ובוחרים ענף `main`. אין צורך למלא Build command ו-Publish
directory — הם נקראים מ-`netlify.toml`. מכאן כל push ל-`main` מפרסם אוטומטית,
ו-Pull Requests מקבלים Deploy Preview.

לבדיקה מקומית לפני push: `npx netlify-cli deploy --build` (או פשוט להריץ שרת
סטטי מתיקיית הפרויקט, למשל `python3 -m http.server`).

## עדכון הנתונים החודשי

1. מורידים את שלושת קובצי הנתונים (xlsx או csv) מ-data.gov.il:
   גמל-נט, פנסיה-נט וביטוח-נט, עם העמודות המקוריות (FUND_ID, REPORT_PERIOD...).
2. מריצים מתיקיית הפרויקט:

   ```bash
   python3 tools/build_dataset.py \
       --gemel gemel.xlsx --pensia pensia.xlsx --bituach bituach.xlsx \
       --prev funds_unified.json -o funds_unified.json
   ```

   הדגל `--prev` משווה לקובץ הקודם ותופס תקלות המרה (ירידה בתקופה,
   קפיצה חריגה במספר הקופות, סטייה בחשיפות). אם בדיקה נכשלת — הקובץ
   לא נכתב והשגיאות מודפסות.

   בנוסף, המאגר שומר לכל קופה היסטוריה חודשית של תשואה וחשיפת מניות
   (עד 24 חודשים) שמזינה את גרפי "מגמה חודשית של התיק" בדשבורד.
   ההיסטוריה נבנית מקובצי המקור ומתמזגת עם הקובץ הקודם דרך `--prev`,
   כך שהיא רק מצטברת מעדכון לעדכון.
3. אם אקסל מציג את קובץ המקור כג'יבריש (`éùéø -àéé. ãé. àéé.`) — הקובץ
   מקודד ב-Windows-1255 ואקסל פותח אותו לפי ברירת המחדל של המערכת. התוכן
   תקין, ו-`build_dataset.py` קורא אותו כמו שהוא. כדי לראות אותו בעין:

   ```bash
   python3 tools/fix_csv_encoding.py bituach.csv          # -> bituach.utf8.csv
   python3 tools/fix_csv_encoding.py bituach.csv --xlsx   # -> bituach.xlsx
   ```

   הכלי מזהה גם קובץ שכבר נשמר משובש מאקסל ומחזיר ממנו את העברית.
   בלי קוד: באקסל, נתונים ← "מקבלת נתונים מטקסט/CSV" ← מקור הקובץ
   "1255: Hebrew (Windows)". לא לשמור קובץ שנפתח משובש — זה מקבע את הג'יבריש.
4. לבדיקה של קובץ קיים בלי לבנות מחדש:

   ```bash
   python3 tools/build_dataset.py --check funds_unified.json
   ```

5. עושים commit ל-`funds_unified.json` המעודכן.

דרישות: Python 3, ו-`openpyxl` אם קובצי המקור הם xlsx (`pip install openpyxl`).

## הנחות הסימולציה

המחשבון ב-`scripts.js` מריץ את היתרה שהוזנה קדימה בשני מצבים. ברירת המחדל
היא הסימולציה ההיסטורית.

| מצב | התשואה השנתית |
|---|---|
| **סימולציה היסטורית** (ברירת מחדל) | סדרות `SIM_RAW_YIELDS`, שנה אחרי שנה: שנה *n* בסימולציה מקבלת את הערך ה-*n* בסדרה, כולל שנים שליליות. |
| **תרחיש ממוצע** | הנחה קבועה: מניות 9% לשנה, אג״ח 5% לשנה (`SIM_AVERAGE_STOCK_YIELD`, `SIM_AVERAGE_BOND_YIELD`), משוקלל לפי החשיפה למניות של התיק. כל מה שאינו מניות נחשב אג״ח. זו הנחה, והמסך מציג אותה ככזו, לא כתשואה צפויה או מובטחת. |

### סדרות התשואה ההיסטוריות: מה ידוע ומה לא

- **מבנה:** שלוש סדרות (סיכון נמוך, בינוני, גבוה), 30 תשואות שנתיות בכל אחת, באחוזים.
- **מקור: לא ידוע.** הסדרות נכנסו לריפו בלי הערה ובלי מקור (קומיט `a24a5e9`,
  מתוך הקוד שנבנה ב-Lovable). ניסיון לאתר אותן ברשת לא הצליח: חיפוש הערכים
  לא החזיר מקור, ואתרי הנתונים שנבדקו היו חסומים בסביבת העבודה.
- **טווח שנים: ככל הנראה 1995–2024, לא מאומת.** אם הערך הראשון הוא 1995,
  השנים השליליות בסדרת הסיכון הגבוה הן 2000, 2001, 2002, 2008, 2018 ו-2022,
  בדיוק שנות הירידה בשוק המניות האמריקאי בתקופה הזו. בסדרה הבינונית: 2001,
  2002, 2008, 2018, 2022. זה דפוס עקבי, לא הוכחה.
- **הסדרות אינן S&P 500.** הדפוס דומה, אבל הערכים לא: ב-2008 (הערך ה-14)
  הסדרה הגבוהה מראה ‎-30.89%, בעוד שתשואת S&P 500 כולל דיבידנדים הייתה כ-‎-37%.
  ייתכן שמדובר במדד אחר, בתיק מעורב או בנתונים אחרי עמלות. לא ידוע.
- **נתונים מסכמים** (ממוצע גאומטרי ל-30 שנה / מינימום / מקסימום):
  נמוך 5.54% / ‎-13.89% / 22.66%; בינוני 8.66% / ‎-16.96% / 30.82%;
  גבוה 10.40% / ‎-30.89% / 35.83%.
- **מה צריך להשלים:** מאיזה מדד או גוף הסדרות לקוחות, ואם הן ברוטו או נטו.

### הנחות החישוב (בשני המצבים)

| נושא | ההנחה |
|---|---|
| התאמה לתיק (היסטורי) | התשואה משוקללת ליניארית לפי החשיפה למניות: 0% ← סדרת הסיכון הנמוך, 50% ← הבינוני, 100% ← הגבוה. |
| תשואה חודשית | המרה גאומטרית, `(1+r)^(1/12) − 1`: שנים-עשר חודשים מחזירים בדיוק את התשואה השנתית. |
| דמי ניהול מהצבירה | **הנחת המודל:** שיעור שנתי שנגבה מהיתרה כל חודש בשיעור של 1/12 ממנו. זו הנחת חישוב; שיטת הגבייה בפועל בכל מוצר לא אומתה. ברירת המחדל: דמי הניהול המשוקללים שהמשתמש הזין. דמי ניהול מההפקדות אינם נכללים. |
| הפקדות | סכום חודשי קבוע, בסוף כל חודש, אחרי התשואה ודמי הניהול של אותו חודש. |
| אינפלציה | הנחה של המשתמש (ברירת מחדל 2%, אמצע יעד בנק ישראל), מומרת לחודש גאומטרית. |
| מה לא נכלל | מס, דמי ניהול מההפקדות, שינוי מסלול לאורך הזמן, והבדל בין תשואת מסלול לתשואה האישית. |

## בדיקות קבלה

`tools/acceptance_test.cjs` מריץ את הדשבורד בדפדפן אמיתי ובודק: נתון חסר
אינו נספר כאפס, שיעור הכיסוי, השוואה אחרי רענון, תשואות מחודש דיווח זהה,
עריכה מהדשבורד, שני מצבי המחשבון, רמות השיתוף, ותצוגת תיק ששותף.

```bash
npm i -D playwright && npx playwright install chromium   # פעם אחת
node tools/acceptance_test.cjs
```
